# 配置

如果你不了解每个配置的实际用途，请保持默认，不要修改。  
所有需要手动修改的文件，都为 `toml` 格式。请不要，也无须手动修改 `json` 格式的数据。

程序运行时，会从环境变量中读取 `SESHAT_HOME` 作为程序的主目录。  
和程序运行相关的数据，都会存放在这里。  
`SESHAT_HOME` 未设置时，使用 `~/.vSoft/Seshat` 作为主目录。

配置文件位于主目录的 `config.toml` 中，若它不存在，程序会自动生成。  
自动生成的文件里，已经预填了默认值。

下面的 `base_url`、`backend_url`、`fallback_url`，均能指向另一个 Seshat 实例。  
v2 及之后版本的 Seshat 已对这种使用方法做了优化。

## bind_addr（监听地址）

若只在本机访问，默认值 `127.0.0.1` 即可。设为 `0.0.0.0` 可将服务开放到局域网或公网。  
请避免直接映射到公网，确有需要时使用反向代理或 VPN 做访问控制。

## api_token（本地 API 令牌）

用于保护本地 API 的 POST 请求，防止其他网页调用。  
首次创建配置时会自动生成一个随机令牌，之后更换可手动修改。  
留空则不校验 POST 请求。

## data_home（数据目录）

数据目录默认存放在主目录的 `/data` 中，这里存放从上游拉取的 json 和图片数据，以及本地索引。  
数据目录的大小，视乎你拉取的条目数量。每个条目大约 20 MB（包含图片和其他数据，仅供参考）。

## concurrency（并发任务）

这包括 `concurrency_info` 和 `concurrency_image` 两个配置项。  
每个后台的任务会建立 4 到 12 个 HTTP 连接，因此请勿设置过高，以免触发限流。

## base_url（上游地址）

这控制后端拉取数据时的请求位置，默认为“番组计划”的 API 端点。  
留空将不能拉取数据，上游 ID 搜索也会隐藏。建议不动。

## access（访问令牌）

拉取匿名访问无法获取的受限条目时，需要配置个人访问令牌。  
在 [番组计划个人令牌](https://next.bgm.tv/demo/access-token) 页面创建令牌，然后填入：

```toml
[access]
bangumi_access_token = "access-token"
```

修改后需重启 Seshat 生效。  
令牌会用于后端拉取数据，也会在回退或自定义后端模式下，由前端请求远程 API 时自动携带。  
如果不是频繁拉取受限条目，建议把有效期设为最短的 7 天，防止令牌泄露。

## proxy（代理）

控制后端拉取数据时使用的 HTTP 代理，用于上游网络受限的情况。  
需要同时填写 `host`（IP 或域名）与 `port`，例如：

```toml
[proxy]
host = "127.0.0.1"
port = 7890
```

留空 `host` 即不启用代理。该代理仅作用于后端拉取（数据与图片），不影响由前端发起的请求。

如果代理工具支持 TUN 模式，也可以不单独配置这里。

## backend_url（后端地址）

控制前端请求数据时访问的后端地址。留空时请求本地后端。  
前端会根据后端的“能力”，来展示功能。详情见下“前端请求行为”。

### 连接到符合 Seshat API 规范的后端

连接到另一个 Seshat 实例时，地址需要写到 `/api`：  
`backend_url = "http://192.168.1.10:12500/api"`

### 连接到“番组计划”后端

你可以将此项设为 `https://api.bgm.tv`，前端就能直接访问“番组计划”来拉取实时数据。

不建议直连“番组计划”，Seshat 的定位是离线查看动画数据库。

### 前端请求行为

- 始终请求本地：页面、静态资源、设置、打开链接
- 始终请求对端：详情、图片、剧集、用户、收藏、搜索
- 优先对端，本地回退：列表、名称索引
- 根据能力，请求对端：ELO、统计、标签、拉取、Tracker、任务、事件、上游搜索

对端缺少能力时，前端对应入口将被隐藏。  
由于 Seshat 目前没有鉴权，请避免将你的服务开放至公网或不可信局域网。

## fallback_url（回退地址）

当请求后端时返回 404 时，将回退到此地址。默认为留空，不启用回退。

若将此项设为 `https://api.bgm.tv`，在本地没有保存某些数据的时候，就能够自动回退到在线端点。  
这使得在有网络的情况下，可以查看到更多数据。

要开启回退，建议先在不设置回退的情况下，完整拉取一遍数据后再开启，确保本地数据正常。
