# 管理数据

## Tracker

Tracker 是记录了多个条目 ID 的列表，用来批量拉取和刷新。

你可以在在“管理数据”页面的“指定 Tracker”选框的输入框中，输入你希望的 Tracker 名称，并点击加号创建。  
或者，你可以自己创建符合格式的 toml 文件。

创建成功后，你需要手动将你希望取得数据的 ID，写入 `ids` 部分。  
然后，就可以在“管理数据”页面进行拉取了。

Seshat 会在以下列出的情况下，创建由 Seshat 维护的 Tracker。

- `_seshat.json`：使用“指定 ID”拉取的条目。
- `user.json`：使用“同步收藏到 Tracker”创建的条目。

不建议手动修改这些 json 格式的 Tracker，因为它设计被程序维护。

## 管理

### 拉取

来源：

- 所有 Tracker 中的新增 ID：本地索引缺少，或核心文件不完整的 ID
- 所有 Tracker：全部 Tracker 中的 ID
- 指定 Tracker：勾选 Tracker，或在输入框中填写 id
- 指定 ID：手动填写动画 ID
- 本地存在的条目：本地索引中的全部条目

详情数据：

- 补充缺失：只处理本地缺失或不完整的条目
- 全量下载并覆盖：重新拉取并覆盖已有详情数据

图片：

- 跳过
- 补充缺失
- 全量下载并覆盖

你可以任意组合想要的数据。  
对于“详细数据”和“图片”，首次拉取请选择“全量下载并覆盖”。

### 上游 ID 搜索

管理页右侧提供上游 ID 搜索，会连接配置中的 `base_url`。  
搜索之后，点击结果右侧的加号，会将 ID 追加到“指定 ID”输入框，可以连续添加多个。  
添加完成后，在左侧选择详情数据和图片策略，再开始拉取。

### 用户数据

刷新用户数据，用于从“番组计划”下载头像、基本信息和收藏。  
同步收藏到 Tracker，会用当前收藏列表建立名为 `user.json` 的 Tracker。

### 危险区

- 重建索引：读取本地 JSON，重建 index 目录，图片索引不重建
- 重建 ELO：根据本地 ELO 对战历史重新计算评分
- 重建全部：删除 `data` 中除 `user` 外的内容，再根据 Tracker 完整重建（不会删除你的 ELO 数据）

## 备份

Seshat 完全依赖 Tracker 中记录的 ID 来拉取数据。  
通常只需要备份主目录下的 `tracker` 文件夹。如果使用了 ELO 评分，还应备份 `user/elo/history.json`。  
依靠这些文件，Seshat 能重建你的内容。

如果需要完全的数据可控，建议备份整个主目录。  
这样可以在完全离线的情况下复现已储存的记录。
